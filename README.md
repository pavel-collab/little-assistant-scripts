# README

В процессе работы я часто пишу небольшие скрипты для быстрых проверок или мелкой автоматизации. Как правило эти скрипты одноразовые или очень узкой направленности, которые имеет смысо хранить только до конца проекта. Но бывает так, что получается написать довольно полезный bash или python скрипт, который я потом переиспользую в других проектах или даже в повседневной жизни. Поэтому я решил выделить эти скрипты в отдельный репозиторий.

## check_openrouter_key.sh

Скрипт проверяет валидность API ключа от OpenRouter, а также проверяет количество кредитов, которые на нем остались. Если, например, вам выдается корпоротивный ключ и вы не имеете доступа к самому аккаунту, если ключ дает вам друг или если это ваш ключ, но вы не хотите заходить в личный кабинет, этим скриптом вы можете проверить количество оставшихся доступных кредитов.

Не забудьте вставить свой API ключ в скрипт
```
./check_openrouter_key.sh
```

## llm_healthcheck.sh

Скрипт пингует llm с OpenRouter и проверяет, отвечает ли она и с какой скоростью. Это нужно, например, если модели вашего провайдера переодически отваливаются или если модель отвечает долго, простым запросом можно заменить время ответа и проверить, не зависла ли модель. Вместо OpenRouter можно использовать любой другой base_url и провайдера, который поддерживает OpenAI совместимый фаормат HTTP запросов.

Не забудьте вставить свой API ключ, указать корректный base_url и выставить нужную модель.
```
./llm_healthcheck.sh
```

## drawio2png.sh

Скрипт рендерит диаграммы `.drawio` в картинки. Понадобился, когда я начал просить агента рисовать схемы: LLM хорошо пишет `.drawio` — это обычный XML, — но чтобы посмотреть результат, файл надо чем-то открыть. Получается конвейер «агент пишет `.drawio` → скрипт → PNG», и картинку можно сразу вставлять в заметку или в документацию, не запуская редактор.

Работает через CLI приложения drawio desktop, поэтому точность полная: что видно в редакторе, то и в картинке. Экспорт идёт headless, окно не открывается, около шести секунд на диаграмму. Альтернативы вроде своего конвертера mxGraph XML → SVG я пробовать не стал: они поддерживают только подмножество возможностей drawio, и расхождение с редактором вскрывается не сразу.

Единственная зависимость — само приложение. Cask ставит и его, и обёртку в PATH, так что после установки команда `drawio` доступна сразу.

```
brew install --cask drawio
```

Без аргументов рендерит все `.drawio` в текущем каталоге, результат кладёт рядом с исходником. Масштаб и формат задаются переменными окружения — кроме PNG умеет SVG, PDF и JPG.

```
./drawio2png.sh                     # все .drawio в текущем каталоге
./drawio2png.sh a.drawio b.drawio   # указанные файлы
./drawio2png.sh path/to/dir         # все .drawio в указанном каталоге
SCALE=3 FORMAT=svg ./drawio2png.sh  # другой масштаб и формат
./drawio2png.sh --help
```

Если хотя бы один файл не отрендерился, скрипт вернёт ненулевой код — удобно вешать в pre-commit хук или в Makefile, чтобы картинки не отставали от исходников.

## export_phoenix_traces.sh

В своих проектах я много использовал phoenix -- сервис для трассировки запросов агентов. Почему-то в WebUI Phoenix я не нашел кнопки экспортировать трассы, но у меня получилось это сделать с помощью bash скрипта. Это нужно например, если у вас большая трасса или если трасс много и нужно их проанализировать, собрать какую-то статистику. В этом случае удобно скачать их в json или jsonb формате и передать агенту на анализ;
